# Проверки SonyX

Все фоновые проверки делаются на самом Mac и ничего не отправляют наружу.
Единственное исключение — проверка 6, и она запускается только вручную.

## 1. Туннель поднят

**Вопрос:** идёт ли интернет через VPN?

**Как:** маршрут по умолчанию для IPv4. Команда `route -n get default`.
Если `interface: utunNN` — туннель работает. Если `en0`, `en1` и т.п. —
трафик идёт напрямую.

**Почему не по имени интерфейса:** номер `utun66` меняется при каждом подключении.
Запоминать его нельзя. Запоминаем правило «маршрут через любой `utun*`».

**Реакция:** нет туннеля → пауза защищаемых программ.

## 2. Страна и адрес выхода

**Вопрос:** из какой страны и с какого адреса мы выходим?

**Как, без запросов наружу:** ядро VPN (у Happ это `xray`) держит соединение
с сервером. Адрес сервера виден в списке соединений Mac (`lsof -i` или `netstat`).
Для протокола VLESS внешний адрес обычно совпадает с адресом сервера.
Страна по адресу определяется по локальной базе GeoIP (например, GeoLite2 Country
или `geoip.dat`, который Happ уже скачивает для маршрутизации).

**Ограничение:** если VPN-сервер пропускает трафик через второй сервер,
внешний адрес будет другим. Для таких случаев есть проверка 6 по кнопке.

**Результат на тестовом Mac (6 ноября 2026):**
- отдельного процесса `xray` нет: Happ держит туннель в системном расширении
  `Tunnel.appex` (процесс `Tunnel`). `lsof -i -p <pid>` работает без root,
  потому что процесс запущен от того же пользователя;
- сервер — `192.0.2.42` (NL), а Cloudflare видит выход `198.51.100.20` (NL).
  Адреса разные, страна одна. Локально мы узнаём страну сервера, не выхода;
- среди соединений процесса `Tunnel` есть прямые — к Ростелекому, Selectel, Яндексу:
  у Happ правило «российское — мимо VPN». Поэтому адрес сервера — не «любое
  соединение туннеля», а адрес с наибольшим числом постоянных соединений на порт 443,
  которые держатся между опросами;
- вчера выход был в Германии (`203.0.113.10`), сегодня в Нидерландах: Happ сменил
  сервер. SonyX в этой ситуации поставил бы программы на паузу и предложил
  «Разрешить Нидерланды».

**Как реализовано (этап 3, `ServerDetector`):** среди установленных TCP-соединений
берутся те, что идут с физического адреса (192.168.x.x) на публичный; программы при
поднятом туннеле ходят с фиктивного адреса 198.18.x.x и в выборку не попадают.
Лидер — адрес с наибольшим числом соединений (не меньше двух). Лидер меняется только
если новый держится два подсчёта подряд; при простое (нет соединений) сервер считается
прежним. После падения туннеля детектор сбрасывается: клиент мог переподключиться
к другому серверу.

**Страна сервера ≠ страна выхода.** Тот же сервер `192.0.2.42` по базе DB-IP — Кипр
(whois говорит Нидерланды), а `claude.ai` видит через него выход `203.0.113.10` в Германии.
Поэтому страна по адресу сервера — ориентир для обнаружения *смены* сервера, а не истина
о том, что видит сайт. Результат проверки 6 запоминается для каждого адреса сервера
(`config.json`, поле `exits`), и пока сервер тот же, SonyX показывает настоящий выход.

**По какой стране принимается решение (с 07.11.2026, `CountryInfo`):** если для текущего
сервера есть запись в `exits` — по стране выхода. Иначе — по базе. Это важно для цепочек:
клиент подключается к промежуточному серверу в России, а выход — в Германии. По базе SonyX
поставил бы паузу зря; по известному выходу — нет. В журнале и `status` рядом со страной
пишется источник: «по базе» или «по проверке выхода 06.11 18:53».

Пока выход для сервера не проверен, подсказка при паузе — сначала `sonyx exit-check`, а не
`allow country`: разрешать страну по базе вслепую нельзя, она может быть не той, что видит сайт.

**Ограничение:** запись в `exits` может устареть — провайдер поменяет цепочку за тем же
входным сервером, а SonyX продолжит верить старой проверке. Поэтому дата проверки показывается
везде, где показывается страна. Автоматически проверка не повторяется (принцип «ничего наружу»).

**Реакция (зависит от режима, см. ARCHITECTURE.md, «Настройки»):**
- лёгкий: страна в запрещённых (встроенный список + чёрный список пользователя) → пауза;
- средний: страна не из разрешённых или неизвестна → пауза;
- жёсткий: адрес сервера не из разрешённых → пауза.

**Что запоминается:** при включении защиты текущие адрес и страна попадают
в разрешённый список. Новые добавляются подтверждением по уведомлению.

## 3. Утечка IPv6

**Вопрос:** может ли IPv6 уйти мимо туннеля?

**Как:**
- `route -n get -inet6 default` — есть ли маршрут IPv6 наружу и через что;
- `ifconfig` — есть ли на физических интерфейсах (`en0` и т.п.) публичный IPv6-адрес.
  Адреса `fe80::...` не считаются: они работают только в локальной сети.

**Результат на тестовом Mac (5 ноября 2026):** маршрута IPv6 нет (`not in table`),
публичных IPv6-адресов нет. Утечки по IPv6 нет.

**Реакция:** маршрут IPv6 через физический интерфейс → **пауза в обоих режимах**,
как при упавшем туннеле. Chrome предпочитает IPv6, если он есть, а `claude.ai` его
поддерживает: сервис увидел бы настоящий адрес. Это не предупреждение, а утечка.

**Как исправить пользователю:** выключить IPv6 на Wi-Fi
(`networksetup -setv6off Wi-Fi` или в настройках сети). SonyX подскажет это в окне.

## 4. Утечка DNS

**Вопрос:** кому уходят DNS-запросы?

**Как:** `scutil --dns` показывает текущие DNS-серверы. Если при поднятом туннеле
первый сервер — домашний роутер (`192.168.x.x`) или провайдерский, запросы уходят
мимо VPN. Провайдер видит имена сайтов, хоть и не содержимое. Сам сервис ИИ
ничего не замечает: запрос к сайту всё равно идёт через туннель.

**Реакция:** предупреждение (значок с восклицательным знаком). Пауза — настраивается.
Это утечка приватности перед провайдером, а не перед сервисом, поэтому не красный.

**Как исправить пользователю:** в VPN-клиенте включить «DNS через туннель»
или в настройках сети Mac указать публичный DNS.

**На тестовом Mac (06.11.2026):** при поднятом туннеле в основной конфигурации серверов
нет вообще — Happ забирает DNS внутрь туннеля. Домашний роутер `192.168.0.1` остаётся
только в scoped-резолвере интерфейса `en0`, который для обычных запросов не используется.
SonyX смотрит только основную секцию `scutil --dns`.

## 5. Часовой пояс

**Вопрос:** не выдаёт ли VPN часовой пояс?

**Как:** сравнить пояс Mac (`systemsetup -gettimezone` или `TZ`) со страной
из проверки 2. Московское время при немецком адресе — признак VPN для сайтов
(пояс читается через JavaScript в браузере).

**Реакция:** строчка в окне («Часовой пояс: Москва, не совпадает с Германией»).
**На значок не влияет.** Исправить это пользователь не может без сбоя своих часов,
а постоянное предупреждение обесценило бы значок.

## 6. Что видит сайт (по кнопке)

**Вопрос:** какой адрес и страну реально видит сервис?

**Как:** запрос к `https://claude.ai/cdn-cgi/trace` — служебной странице Cloudflare,
которая возвращает адрес (`ip=`) и страну (`loc=`). Спрашиваем сам сервис, а не
посредника: если в VPN-клиенте есть правила маршрутизации по доменам, `claude.ai`
может идти другим путём, чем остальной трафик, и нейтральный сайт этого не покажет.
Хост настраивается, можно добавить `chatgpt.com`.

**Правила:**
- запрос делает сам SonyX своим HTTP-клиентом, без cookie; браузер не участвует,
  поэтому запрос не привязан к аккаунту;
- вручную (`sonyx exit-check`, кнопка) и автоматически (с 07.11.2026, см. ниже);
- только если проверка 1 прошла. Без туннеля кнопка неактивна: ответ и так известен
  (сайт увидит домашний адрес), а запрос оставил бы в логах связку
  «домашний адрес ↔ адрес VPN»;
- запрос физически привязан к туннелю: идёт через `Network.framework` с требованием
  интерфейса типа «туннель», и после соединения проверяется, что путь через `utun*`.
  Если туннель упал в миллисекунду между проверкой 1 и отправкой — запрос не уйдёт вовсе;

**Автопроверка (отступление от «только по кнопке», решено 07.11.2026).** Без неё лёгкий и
средний режимы с автовыбором сервера в VPN-клиенте дают ложные паузы: новый сервер → выход
неизвестен → страна по базе (часто неверная) → пауза зря. Сторож проверяет выход сам:
- появился незнакомый сервер — обязательно;
- переподключение к знакомому серверу (туннель упал и поднялся, Mac проснулся, запуск SonyX) —
  ловит подмену выхода за тем же сервером, которую провайдер сделал с перезапуском;
- раз в N минут на одном сервере (`recheckMinutes`, по умолчанию 30, 0 — выкл) — ловит тихую
  подмену без обрыва; редкий случай, поэтому настраивается;
- после неудачи — повтор не раньше чем через минуту; до тех пор решение по тому, что известно.
Пока ответ не пришёл, решение принимается по базе (при сомнении — пауза), так что утечки нет.
В типичный день на одном сервере — ноль запросов сверх плановых; с автовыбором — один на
каждое переключение. Выключить: `sonyx autocheck off`.
- необязательная галочка «подробная диагностика» — дополнительный запрос
  к `1.1.1.1/cdn-cgi/trace`. Если адреса у `claude.ai` и `1.1.1.1` разные,
  трафик к `claude.ai` идёт отдельным маршрутом.

**Подтверждено 06.11.2026 на тестовом Mac:** `1.1.1.1/cdn-cgi/trace` показал выход
`198.51.100.20` (Нидерланды), а `claude.ai/cdn-cgi/trace` в тот же час — `203.0.113.10`
(Германия). Happ ведёт `claude.ai` через другой сервер, чем остальной трафик. Нейтральный
хост дал бы неверный ответ.

**Почему это допустимо при принципе «ничего наружу»:** запрос уходит с адреса VPN,
который Anthropic и так видит каждый день при работе с Claude. Новой информации
ни у кого не появляется. Фоном к `claude.ai` по-прежнему не ходим.

## 7. Новые процессы

**Вопрос:** не запустилась ли защищаемая программа, пока туннель лежит?

**Как:** регулярный просмотр списка процессов (`ps` или `proc_listpids`).
Новый процесс из списка защищаемых при неразрешённом состоянии сразу замораживается.

## 8. Страна в списке сервисов

**Вопрос:** работает ли сервис ИИ из страны выхода вообще?

**Как:** внутри SonyX лежат списки стран, где официально доступны Claude и ChatGPT
(по справкам Anthropic и OpenAI). Страна из проверки 2 сравнивается со списком.
Запросов наружу нет, списки обновляются вместе с программой.

**Cursor** своего списка не публикует: модели в нём доступны там, где их разрешает
провайдер (Anthropic, OpenAI, Google). Для Cursor показываем «по правилам Anthropic».
С сентября 2026 Cursor фактически закрыт для России (пункт ToS об экспортном
контроле США).

**Реакция:** страна не в списке → предупреждение в окне. Без паузы: это не утечка,
а подсказка, что сервер VPN выбран неудачно.

## Когда проверки запускаются

- При старте SonyX (всё сначала заморожено до первой успешной проверки).
- По событию смены сети от macOS (SystemConfiguration / `route monitor`).
- После пробуждения Mac из сна.
- Страховочно раз в несколько секунд опросом.

## Реакция и возврат

1. Событие → мгновенная пауза защищаемых программ, всего дерева процессов.
2. Проверки 1 и 2. Прошли → пауза снимается, обычно меньше чем за секунду.
3. Не прошли → программы стоят. Уведомление macOS с кнопками:
   «Разрешить этот адрес», «Разрешить страну», «Пауза защиты на час».
4. Туннель вернулся → проверка снова, пауза снимается сама.

Закрывать программы по таймауту первая версия не будет (см. QUESTIONS.md).
